# Skyrim NPC Web Application --- Phases and Testing Plan

## Phase 0 --- Repository Audit

### Goal

Understand the existing Tkinter implementation before changing it.

### Tasks

-   Inspect `transformer_chatbot.py`.
-   Inspect `training.ipynb` for model/tokenizer assumptions if
    required.
-   Identify vocabulary loading.
-   Identify model architecture and checkpoint loading.
-   Identify text preprocessing.
-   Identify response generation.
-   Identify Vosk initialization and microphone handling.
-   Identify Silero initialization.
-   Identify TTS generation and audio format.
-   Identify existing conversation state.
-   Identify the soundtrack file and current playback behavior.

### Test

Run the existing Tkinter implementation.

Verify:

-   text input works
-   Transformer response is generated
-   TTS works
-   voice input works if already implemented
-   the existing implementation remains functional

### Exit Criteria

There is a written understanding of the existing inference pipeline and
no unnecessary model logic has been rewritten.

------------------------------------------------------------------------

# Phase 1 --- Backend Foundation

## Goal

Expose the existing Python pipeline to the web without changing model
behavior.

### Tasks

Create a FastAPI backend.

Implement:

-   application startup
-   model loading once
-   vocabulary loading once
-   Vosk initialization once
-   Silero initialization once
-   text inference service
-   TTS service
-   error handling
-   health endpoint

Suggested endpoint:

``` text
GET /api/health
```

### Test

Call the health endpoint.

Verify:

``` text
HTTP 200
backend ready
model loaded
```

Then test text inference independently.

### Exit Criteria

The backend can receive text and return a real Transformer response.

# Phase 12 --- Failure and Recovery

## Goal

Make failures graceful.

### Test These Cases

-   backend unavailable
-   backend starts late
-   model fails to load
-   microphone denied
-   microphone disconnected
-   Vosk error
-   Transformer error
-   TTS error
-   browser audio error
-   network timeout
-   empty transcription
-   repeated submission

### Required Behavior

The scene must remain visible.

Do not replace the entire application with:

``` text
BLACK SCREEN
```

or an unrecoverable overlay.

Provide:

-   readable error
-   retry
-   return to idle where appropriate

### Exit Criteria

Every major failure has a visible recovery path.

# Phase 20 --- Final Optimization and Release

### Final Tests

-   desktop browsers
-   different resolutions
-   slow network
-   backend restart
-   long conversations
-   microphone denial
-   audio interruption
-   repeated conversations
-   memory growth
-   GPU performance

### Final Principle

Do not add an effect simply because it is technically possible.

Every visual or audio feature must improve immersion enough to justify
its performance and complexity cost.
